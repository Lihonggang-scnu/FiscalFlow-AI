# GPT-6 Pro 建议落实清单

## 作品主线

以“变化后继续把事情办完”为核心：系统理解多票补充与更正，根据当前票据、规则和任务计算待办及变化，把结果同时交给对话和工作台；用户可以继续补充、暂缓、确认保存或撤销。目标是减少重复说明，让更正只影响相关事项。

## 已接入升级版

| 能力 | 实际工作方式 |
|---|---|
| 任务账本 | 记录任务、草稿、暂缓、更正和操作事件；按用户、企业和当前任务形成状态。 |
| 工作面与变化 | 从当前业务数据和任务计算待补、草稿、暂缓和完成状态，并列出受影响与状态不变的票据。 |
| 依据与版本 | 每个目标带任务、票据、规则和草稿事件引用；当前采用同范围重查与计算。 |
| 聊天与三页面草稿 | 对话中的任务草稿可在票据页更正并暂存，办件页与新对话可继续读取。 |
| 保存与撤销 | 发票只写用途和备注；保存后回读；可撤销本人最近的对应字段修改，必要时恢复待办。 |
| 旧回执处理 | 恢复已提交操作时重新读取当前值，区分历史回执与后来发生的修改。 |
| 企业范围 | 同轮跨企业操作按具体动作确定企业；切换与修改有先后关系时在同一用户轮次内分步执行。 |
| 规则变化预览 | 在不修改规则的情况下计算门槛变化对发票及任务的影响。 |
| 上下文 | 保留当前任务、必要原话和完整工具交换；较早记录仍可按引用恢复。 |
| 问询 | 结合已知草稿和暂缓事项排序；可选地模拟全部、部分和未知三类回答。 |
| 失败场景 | 真实模型测试失败时，保留失败前的独立数据和单轮请求，便于针对性重跑。 |

三页面交互已经在隔离数据中完成草稿暂存、新会话恢复、正式保存、撤销和完成后再更正的浏览器检查。

## 继续推进

1. **真实模型主流程**：在授权的 DeepSeek 闲时预算内，运行多票草稿、更正、部分保存、跨会话接续、工作台更正与最终保存；再跑长对话、规则预览、跨企业和权限场景，按失败场景逐一修复。
2. **旧版与升级版对比**：使用同一组输入、相同官方起始数据和模型，分别测试跨会话草稿、同轮跨企业操作和长对话更正；观察正确办理、重复询问、调用次数和费用。
3. **企业工作台 C1 的共享**：现有企业版另有经办人回复、会计确认和复核流程；需要将它的逐票草稿与对话办件进一步接通，并处理企业角色、月份及任务模型与比赛版之间的差异。
4. **依赖机制增强**：当前已经记录直接依据并重算工作面；继续针对规则、票据、草稿和用户更正验证影响范围，并探索更细的可替代支持关系。
5. **问询实验**：已用五个固定模拟场景比较逐票、排序与可选前瞻；排序减少了模拟轮次，前瞻暂未比排序更好。后续用更丰富的模拟用户及真实交互筛选。
6. **最终模型与交付**：准备 Qwen 模型配置，取得实际评审接口后验证真实工具调用与关键业务场景，再整理可启动版本和说明材料。

## 验收重点

- 发票和银行数据、规则及权限按当前数据判定；不同企业同号票不得混淆。
- 用户没有要求保存时仅保留草稿；明确保存后真实回读，重复或中断不重复写入。
- 单张更正保留其他票据的有效草稿；暂缓事项仍然存在且不反复追问。
- 新对话能恢复任务和草稿，但不会因为恢复自动写入。
- 旧保存回执和晚到结果不能覆盖后续更正；取消任务后新任务不继承旧任务的待办状态。
- 三个页面和对话对当前办件给出一致状态；规则预览不改变现行规则或发票。
- 对照实验分别记录真实模型完成情况、沟通轮次与费用；Qwen 测试单独记录。
