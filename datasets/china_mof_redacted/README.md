# TaxAgentHarness 中国企业测试来源与小样本

整理日期：2026-11-10。中国公开标准和本地可处理的小样本优先；国外材料只补充重复件、多币种和复杂单据情境。此目录提供场景和测试数据，不提供税务结论。标准样例中的税率、期间和金额仅表示样例票据内容，不作为中国税率或会计规则。

## 可立即用于国内测试的数据

财政部实例中可复用的字段信号：开票日期与受票方会计期间可能不同；受票方记录会带已勾选、已入账、已支付、红字状态；银行对账单带期间、币种、交易金额和借贷代码。redacted_examples.csv 是最快入口，测试和演示应使用脱敏副本。

MOF-CN-01/02 是全电发票会计样例；MOF-CN-03 是 2021-08 银行对账单；MOF-CN-04/05 是银行回单开具方/接收方；MOF-CN-06/07 是同一普通发票的销方/受票方实例（开票日 2020-03-28，会计期间 2020-08，价税合计 266.00 CNY，税额分项 34.74 与 -4.14、总税额 30.60）；MOF-CN-08/09 是同一专票的销方/受票方实例（价税合计 98,000.00 CNY）。当前选取的官方 XML 样例红字标记均为 false；红字流程以税务总局官方说明另构造场景。

## 可直接改造成任务的中国场景

| 场景 | 输入/外部变化 | 期望检查 |
|---|---|---|
| CN-01 跨期入账 | 同一蓝字发票开票日期与会计入账期间不同 | 界面并列显示两个期间；用户说“查上个月”时不得把会计期间和发票日期混为一谈 |
| CN-02 红字发票等待对方确认 | 蓝字票已被勾选或入账，销方发起红字确认单 | 记录发起方、确认方、原蓝字票引用和部分/全额范围；对方确认前不能视为已红冲 |
| CN-03 未确认蓝字票直接发起红字 | 蓝字票用途、入账状态均未确认 | 按官方说明构造可由销方发起且无需对方确认的分支；确认单未完成时仍保留待办 |
| CN-04 红字撤销边界 | 红字确认待处理后被撤销，或红字发票已开具后提出撤销 | 前者按确认单状态处理；后者不能误当作删除原蓝字票。具体状态沿用税务局最新流程 |
| CN-05 部分退货/折让 | 用户说“这张只退三件，余下照旧”，但只给了部分数量或金额 | 先补足作用对象和冲红范围；保留蓝票和红票两条记录，不能把整张票直接改成零 |
| CN-06 流水与发票碰巧同金额 | 对账单出现与某张发票相同金额，但没有唯一业务引用 | 只提示候选，不直接认定该款是这张发票的付款 |
| CN-07 多张口语补资料 | “A 是办公采购，B 和刚才那张一样，C 我问一下；先别做账。” | 共享用途只映射到明确范围；C 暂缓；当前轮明确要求前不确认保存 |
| CN-08 已发过但工作台仍缺 | “我上周发给你们了，别再找我。” | 搜索来源记录并展示匹配/不匹配依据；同一附件重复上传不重复建票，找不到时只问缺少的资料 |
| CN-09 同号票跨企业或来源 | 两企业或不同导入源出现相同票号 | 用企业和票据来源身份定位；同号不覆盖，不把跨企业数据合并 |

CN-02—CN-05 由国家税务总局 2024 年问答支持；CN-01、CN-06 来自财政部公开电子凭证实例的字段；CN-07—CN-09 是将公开实务痛点改写成的测试提示。后几项是情境设计，不代表原帖的数量估计或税务结论。

| 来源 | 公开描述的痛点 | 可转测试任务 |
|---|---|---|

## 隐私、许可与使用边界

- `invoice_import_template.csv` 用“样例销方”替代原名称，只保留 2 张发票的日期、CNY 金额和类别；将 `purpose` 留空。可映射到现有企业导入列，创建待补任务。
- 财政部原始公开包保存在 `data/china_mof_standard/` 作为来源备查，其中实例文件包含纳税人/账户类标识。请仅在代码和用户流中使用 `redacted_examples/` 与派生 CSV；不要在日志、截图、提示词或对外材料中引用原始标识。
- MOF 脱敏副本仅遮盖主体名、税号、银行账号、票号、联系方式和自由文本；金额、日期、会计期间与状态值保持样例原值。它们是演示结构样例，不代表统计分布或通用业务规则。
- 票据、银行对账单、红字事件分开建对象。只有票面引用、红字确认状态和会计/业务规则都已核实后，才生成对应的业务动作；金额相同不能单独证明结算匹配。
- 本目录没有模型权重、凭据或真实客户数据；未调用模型、付费 API 或受限数据服务。
