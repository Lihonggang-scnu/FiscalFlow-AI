# 财税 Agent 工作台

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要面向代账机构会计，企业版另有复核主管与经办人角色。产品目标沿用用户已批准的企业落地方向。

## Product Purpose

通过自然语言查询金额、核实票据用途、补充并保存信息、接续未完成任务。企业版支持经办人回复拆成逐票草稿，再由会计确认、复核。

## Operating Context

会计在桌面浏览器中连续办理不同客户的月度票据工作。当前为内部交付及比赛模拟环境。

## Capabilities and Constraints

- 候选 Chainlit 工作台在同一会话内提供 A 办件、B 对话、C 票据核对三种视图；切换视图不重建 Agent 会话。
- B 保留持久历史、查看、继续、复制、展开收起和原生 Chainlit composer；使用模拟用户 U001/U002。
- 8011 企业工作台仍是独立服务和数据库；不能表现为已接入候选 Chainlit 的审批流程。
- 模型理解意图，程序执行权限、金额计算与保存；用途必须来自用户提供的实际业务信息。
- 保留用户数据与历史，优先复用现有环境、代码和业务服务。

## Candidate A/B/C Views

- **A 办件视图**：按当前用户、企业和所选月份显示真实用途补全任务、target/pending 和目标发票详情；仅展示当前 Agent 会话中已保存且当前用户仍有权访问的最近对话。
- **B 对话工作区**：沿用同一 Chainlit 会话、原生聊天、历史与资料侧栏；切换页面不会发送消息或改变企业/期间。
- **C 票据核对台**：按企业和期间显示业务库中的发票编号、开票日期、销售方、项目、金额、用途与备注；用途状态由 `TaxService.list_missing_purposes` 的规则结果给出。
- 可编辑字段只有用途和备注；保存必须由用户显式点击，并通过修改权限、revision 和幂等键检查。
- 当前业务库不包含票据影像、税率字段、预付款/支付状态或多人办件讨论；这些内容不属于候选 UI 功能。

## Product Principles

让真实办理工作决定布局；明确当前客户、任务范围和保存结果；企业与用户数据隔离；以完整可用模块交付。

## Brand Commitments

用户明确拒绝千篇一律的渐变、圆角卡片与大标题组合。需要成熟企业软件的交互体验与有辨识度的设计。本地项目关联云帐房比赛，不代表云帐房已部署的官方产品。
