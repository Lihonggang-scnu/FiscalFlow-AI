# 产品升级建议与界面验收

本轮以现有代码、内部交付资料和实际手动体验为依据。界面升级集中在 8010 聊天入口；下列涉及企业业务整合的项目是后续建议。

## 后续升级优先级

| 优先级 | 升级 | 用户价值 | 验收条件 |
| --- | --- | --- | --- |
| P0 | 聊天与企业工作台打通 | 会计从问答直接进入对应待办、请求和复核 | 登录身份、授权客户及业务上下文一致；从聊天打开对应工作项并完成闭环；切换企业或退出后清除可见的旧客户内容；比赛与企业数据继续隔离 |
| P0 | 接入机构账号及客户授权 | 本地角色权限可以用于实际团队 | 接入机构确定的身份来源；会计、复核、经办人权限一致；撤权在两个入口生效；模型不能扩大身份或企业范围 |
| P1 | 跨月份待办总览 | 迟到资料和历史退回项不会被月份筛选隐藏 | 集中查看未完成、待复核、退回、迟到回复；可返回原工作项；已关闭月份快照和导出保持一致 |
| P1 | 大批量请求自动分批 | 会计不必自行把超过20张票的请求拆成多份 | 21张以上可分批处理并看到总体进度；失败批次可续办；建议与原票、原话对应；会计确认后才写入，重试不重复保存 |
| P0，依赖试点材料 | 真实机构部署及可靠性验收 | 验证真实业务中的收益和运行稳定性 | 获授权真实样本走完导入、办理和结果接收；在目标环境验证备份恢复、重启、升级回退；记录完整期间的处理耗时、失败续办与复核返工 |

依据：`README.md` 的双入口说明；`src/taxharness/enterprise/auth.py` 的现有身份和角色管理；`enterprise/service.py` 的按期间/状态查询和后续任务；`enterprise/agent.py` 的20张票限制；`docs/企业版内部交付验收报告_2026-10-27.md` 的实测与未完成范围。

本轮不重复建设已完成的导入、逐票草稿、会计确认、独立复核、关闭快照和CSV导出。接入真实机构前需要对方提供身份授权方式、结果接收格式及获授权试点数据。

专项核查：`enterprise/service.py:list_work_items` 中，管理员分支先进入 `if user["is_admin"]: pass`，导致后面的企业过滤分支被跳过。代码显示管理员传入企业筛选时可能仍返回全部企业工作项，需要用多企业管理员场景复现并修正筛选；这是查询结果范围问题，当前尚未在本轮运行复现。

## 本轮界面验收条件

- 历史从服务器持久记录加载；新建、刷新、继续对话后原记录仍可查看。
- 历史在独立面板浏览，支持搜索与筛选；搜索覆盖范围有明确说明。
- 回合与长内容可以展开、收起；关闭面板后可再次打开。
- 单条回复与整段对话可以复制；复制完整原文，包含表格，成功失败有明确反馈。
- 用户切换后历史与内容按权限隔离；打开和继续时仍由服务器校验。
- 桌面和窄屏布局可用，控件有键盘焦点，输入区与主要操作可达。
- 浏览器验收使用禁用模型的独立数据副本；业务库、偏好、checkpoint和历史原文不因回看而变化。

## 第一版界面改造（已由B版替换）

8010 已启动新版工作台。首页、输入区与对话档案采用统一深蓝/青绿样式；历史列表进入独立可关闭侧栏，支持当前页筛选和分页。每个历史回合可展开、收起；单条回复和整段对话可以复制原始 Markdown，并有结果反馈。较长的新回复保留完整原文并提供收放；过程诊断默认折叠且有关闭入口。

## B 对话工作区实现记录

用户选择的 B 方向已实现并启动于 8010：首屏去掉宣传型欢迎区，桌面用左侧历史、中间原生 Chainlit 对话、右侧企业资料区。历史列表继续由服务器按用户、业务库、checkpoint 和企业权限筛选；搜索范围为当前页，支持分页、查看和继续。

“查看”只在右侧资料区显示只读历史，可返回当前资料，不切换 Agent 会话。“继续”在中央对话区恢复已保存的用户消息和助手原文，长回复仍可展开和复制，然后在同一个 Agent session 中接着发消息。恢复显示仅读取 AgentStore 已保存回合，不运行工具、不重放操作。

右侧资料默认不选月份；月份只过滤资料区，不写入对话已确认的月份。选择月份后可切换发票、规则和任务；发票下拉一次查看一张。C001 2026-09 适用的用途规则是 R002 2.0，C002 2026-09 适用的用途规则是 R003 1.0。切换用户/企业会清除旧企业可见票据。

Edge 使用隔离 8015 副本实际检查：1440px 三栏、390px 历史和资料抽屉、当前用户和企业、明暗主题、复制、历史查看及继续、切换企业和用户隔离。手机滚到最新按钮已移到正文旁，不遮挡文字；选票可在关闭和重新打开资料后保留，键盘切换后焦点不丢失。

实际读取 U001/C001 2026-09：任务目标 F003/F009、待处理 F009；F009 备注“配件具体用途待经办人确认”、用途为空。U002 的任务列表为空，只能访问 C001；切到 C002 后显示 R003 1.0。测试过程没有更改用户业务库、偏好、checkpoint 或原12回合，新增 DeepSeek 调用为0。

隔离真实业务库中的模拟回合测试验证：保存 F009 用途后，桌面资料区重新读取到新值；读取数据库失败时资料区提示重试。该检查使用模拟执行器，不代表本轮重新实调了 DeepSeek。UI、历史和回复定向检查23项通过；独立设计复核对其提出的两处视觉问题复验后给出 ship（该结论限于实际复核范围）。
