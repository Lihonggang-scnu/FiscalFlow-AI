# 云帐房财税 Agent Harness 设计说明

版本：2026-10-26　适用材料：初赛业务规则 1.1.0

---

## 第 1 页：目标、流程与总体架构

本作品面向三个共用场景：查询指定企业和月份的发票总额、银行收入与支出；按用户明确要求补充发票用途或备注并保存回查；检查缺少用途的发票并在多轮对话中继续处理。所有企业、用户、发票、银行流水和规则均为比赛模拟数据。程序不执行真实记账、付款或申报。

系统由四层组成：

```text
Chainlit / CLI / 连续聊天
            ↓
AgentRuntime：理解、追问、选择工具、维护 session
            ↓
确定性服务：权限、金额、规则选择、任务、发票白名单写入
            ↓
独立 SQLite：业务库、偏好库、Agent ledger/checkpoint
```

AgentRuntime 使用现有 LangChain `create_agent`/LangGraph。Chainlit 只负责本机交互、身份/企业选择、停止和过程展示，不复制业务编排。用户和企业由程序绑定；工具不允许模型填写身份来扩大权限。金额使用整数分计算，业务写入只允许发票用途和备注，并经过权限、版本、幂等和回查。

默认 UI 业务副本位于 `artifacts/chainlit/`，费用账本仍使用 `artifacts/agent/agent.sqlite3`。官方原始材料复制到 `data/` 仅供初始化读取，当前业务数据不回写材料。

## 第 2 页：记忆、规则和模型边界

### 任务记忆

任务按 `user_id + company_id` 隔离，每个范围最多一个未完成任务。`all_missing` 每次接续都重新读取当前发票和当前规则；保存成功后刷新待办。`selected` 只按用户明确指定的发票办理，不因规则门槛变化丢失目标。取消/删除任务不撤销已经保存的发票字段，已完成历史不会因后来规则变化自动重开。

### 长期偏好

只有用户明确说“以后”“记住”“长期按这个方式”时才保存受控表达偏好。偏好独立存储，支持用户通用和用户-企业范围；企业值覆盖同名通用值。支持语言、详略、回答顺序、金额排列和回答格式。偏好不能改变权限、规则、金额、发票字段或任务状态；本轮临时要求优先但不持久化。

### 规则知识

规则用 `(rule_id, version)` 保留正文、企业范围、生效日期、状态和结构化 `condition`。用途条件由程序执行：`all` 表示每张必填，`amount_gte` 使用整数分门槛；未知条件保留可查但返回 `cannot_determine`。同企业同 kind 同生效日期出现不同最新规则时返回冲突。停用最新版本不会静默复活旧版本；需要重新使用旧条件时，导入并显式启用新的更高版本。

规则维护是本机可信 CLI，不开放给 Agent。Agent 只能读取适用规则、名称、版本和实际执行条件。规则失效时，任务保留原 pending 并在上下文给出 warning；独立金额查询仍可继续。

### 模型与程序分工

模型负责自然语言理解、缺失信息追问、工具选择和业务表达；程序负责身份、ACL、金额计算、规则选择、条件执行、任务状态、字段白名单、revision、幂等和持久化。模型声称“已保存”不构成事实，只有程序返回成功才算完成。

## 第 3 页：界面、记录、验证与取舍

Chainlit 使用 `ChatSettings` 选择用户和企业，切换身份会先取消旧 worker，再请求 Chainlit 新 thread 清除旧消息；新 thread 重新校验 ACL 并加载当前任务/偏好/规则。同步 Agent 调用运行在后台 worker，停止请求不会提前关闭仍在运行的 runtime。页面普通回复隐藏内部编号，折叠的“本轮过程”显示本轮实际模型 input、有效偏好/任务/规则、tool call/result 和状态。

运行记录分层保存：Agent ledger/checkpoint 用于运行恢复；参赛包只导出选定且脱敏的输入、工具、结果摘要，不携带 raw SQLite、密钥、虚拟环境或完整历史账本。共享 ledger 不因更换 UI 业务副本而重置。

已完成的确定性和真实业务核对包括：官方五条初始规则、权限/金额/字段限制、任务创建/接续/保存/取消/删除、长期偏好 CRUD 与新会话、规则版本门槛变化与任务刷新、Chainlit 本机 HTTP 启动/停止，以及 Edge 中的身份切换、月份追问、金额查询、任务保存和跨新对话接续。真实演示视频和最终 ZIP 已生成，不把单次状态码当作模型质量结论。

本设计选择轻量本地 SQLite、单 Agent 和受控结构化条件，避免引入向量数据库、复杂规则引擎、后台账户体系或多 Agent 编排；这些取舍直接服务于比赛的三个可核对业务场景。来源复用仅保留 `safe_case_json` 的小型适配思路和已安装依赖的公开能力，其余模块为本项目自建，不依赖来源项目路径。

本轮完整测试已在中文及含空格目录的新venv中仅按依赖清单安装，补齐Windows时区数据后通过启动与业务检查。最终核心实调46轮连续复跑两遍均通过；21轮对话、外部数据更新后重复查询、两种凭据方式和跨进程回执恢复分别检查。详细范围、初测失败及修复记录见《完整测试报告_2026-10-26》。

当前边界：身份选择为本机模拟入口；用途规则自动执行限于 `all`、`amount_gte`、`none`；模型输入保留最近8轮及当前任务/偏好，尚未实现动态token摘要。跨企业未完成任务集中提示、规则原文与执行条件矛盾的导入拦截尚未实现；最终回复已在途时，Stop后仍可能收到该回复。后续优先完善这些体验，再按复赛要求扩展条件组合和故障处理。
