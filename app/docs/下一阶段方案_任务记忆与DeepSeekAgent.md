> 当前修订：用户要求按完整模块交付，不以 MVP 或首轮演示为开发目标。请阅读同目录《下一阶段方案_完整任务管理模块.md》。本文件保留为前一版方案；其中 US$0.50 与 20 次请求只是旧预算草案，不构成调用授权。

## 1. 这一阶段要做出的效果

用户能够用自然语言查询财税数据、检查缺少用途的发票、补充用途并保存。关闭程序或换一个新会话后，仍能接续同一用户、同一企业的未完成事项；用户明确要求记住的表达偏好，也能在新会话使用，并可查看、更正和删除。

当前已完成的 Excel 导入、金额计算、权限、规则选择、用途/备注保存、版本检查和幂等处理继续使用。实现重点放在把这些能力接入实际对话，不另建通用 Agent 平台。

## 2. 技术取舍

采用 **现有 Python 环境 + LangChain create_agent / LangGraph + SQLite + DeepSeek**。

- 继续用 `E:\AI-Chem\ChemIntent\.venv-cpython\Scripts\python.exe`，不创建新环境。Luna 本次已确认 `create_agent`、SQLite checkpointer、ChatOpenAI 可导入；环境内 LangGraph、LangChain OpenAI、HTTPX 已具备。
- 用 `langchain.agents.create_agent` 完成模型与工具之间的循环。它属于已安装的 LangChain/LangGraph 同一技术栈，能够复用现有项目经验。
- 当前任务不需要 DeepAgents 附带的文件操作、子 Agent 和规划能力，因此选该栈更小的入口；不迁移到其他框架。
- 工具直接包装 `TaxService` 和新增记忆服务，不新增独立网关、签名合同、事件溯源或插件框架。工具入口通过 schema 校验一次，后面传递明确类型。
- 对话和工具历史由现成 checkpointer 保存；当前任务、用户偏好和业务事实各有自己的存储位置和用途。
- 首版先提供交互式命令行。完整界面、向量检索、多模型比较留到真实对话跑通以后。

```text
用户选择身份与企业 → 输入自然语言
                         ↓
运行器加载：当前任务、明确偏好、必要对话
                         ↓
create_agent + DeepSeek：理解、追问、选工具、根据结果继续
                         ↓
现有财税服务 / 规则读取 / 任务与偏好管理
                         ↓
SQLite 实际结果 → 模型回复 → 保留下一次要继续的事项
```

## 3. 三类状态如何分工

| 内容 | 保存在哪里 | 再次使用时如何处理 |
|---|---|---|
| 发票、流水、已保存的用途/备注 | 已有业务表 | 重新查询当前值；金额由程序计算 |
| 当前任务的月份、待补发票、下一步 | 新增 tasks 表 | 换会话可恢复；继续办理前重新查规则和相关发票 |
| 用户明确要求的稳定表达偏好 | 新增 preferences 表 | 按当前用户/企业加载，可查看、更正、删除 |
| 对话、工具消息、模型循环进度 | LangGraph SQLite checkpointer | 保留同一会话上下文；新会话通过任务与偏好恢复业务连续性 |

不会把某次查询金额、旧规则内容、某张发票用途当作长期偏好。金额、月份与业务对象优先交给业务库和当前任务管理。

## 4. 任务管理做多大

初版只需要一张“当前任务”表：

| 字段 | 用途 |
|---|---|
| user_id、company_id | 联合唯一键，保证每用户/企业最多一个当前未完任务 |
| task_id、kind | 标识本次事项及类型 |
| month | 用户已明确的业务月份；未知时留空并追问 |
| pending_invoice_ids | 需要继续处理的发票编号 |
| next_step | 简短的下一步或待补信息 |
| status | open、completed 或 cancelled |
| updated_at | 最近更新时间 |

不额外维护通用任务 DAG、复杂历史任务恢复和任务调度器。已有操作记录能够记录任务更正与结束。

行为约定：

1. 一次能回答完的金额查询不强制创建持久任务。出现缺信息或需要连续补用途时，建立或更新任务。
2. 同一用户/企业的新会话读取当前任务，不复制旧金额。保存用途后重新查当前缺项，再更新待办列表。
3. “再查一下 8 月金额”作为临时查询，不覆盖正在处理的 9 月补用途任务。“改为处理 8 月”是明确变更，直接更新任务；表达不清才追问。
4. 切换企业时先按已有权限判断，加载该企业自己的任务；原企业任务保留，不把发票和待办转移过去。
5. 用户可说“我还有什么没做完”“把月份改成……”“取消这项任务”“删除这项任务”。取消或删除后，新会话不再自动继续。
6. 待办是否减少以实际保存和重新查询结果为准，不以模型一句“完成了”为准。

## 5. 长期偏好做多大

新增 preferences 表，联合键使用 `user_id + company_id + preference_key`，保存偏好值、来源用户消息及更新时间。第一版全部按用户/企业隔离，不建设跨企业共享、全局继承或向量记忆。

优先支持“以后回答简短些”“先说结论，再给必要依据”等稳定表达偏好。偏好不能改变业务规则、权限、金额口径或省略赛题要求的必要规则依据。

- 用户明确要求“记住/以后按这个方式”时保存，通常不追加一轮机械确认；只是临时要求则只用于本轮。
- 查看：列出当前范围已保存的偏好。
- 更正：按用户明确要求替换旧值，后续会话使用新值。
- 删除：删除活动偏好，不再注入新上下文。内部必要操作记录与活动记忆分开，操作记录不用于重新召回已删除偏好。
- 运行器附加真实的来源用户消息标识；不让模型填写 `authorized=True` 或 `explicit_user=True` 作为授权证明。

明确偏好意图仍由模型理解，不用一组“出现某个词就保存”的关键词分支代替理解。是否误记、是否漏记，用真实对话检查。

## 6. 最少的六类工具

| 工具 | 连接方式与目的 |
|---|---|
| query_amounts(month) | 包装现有 query_all，一次取得发票、银行收入、支出及规则依据 |
| check_missing_purposes(month) | 包装现有缺用途检查，返回实际发票和适用规则 |
| save_invoice_fields(invoice_id, fields, expected_revision) | 包装已有用途/备注写入，继续使用权限、版本、幂等和回查 |
| read_rules(kind, month) | 读取当前企业和月份适用的规则，提供名称、版本、必要原文 |
| task(action, ...) | 查看、更新、结束、取消或删除当前任务 |
| preferences(action, ...) | 查看、新增/更正或删除当前范围偏好 |

用户身份和企业由运行器绑定，不出现在模型可填写的身份参数里。幂等键由程序生成并关联当前用户消息及具体写入动作；同一动作重试使用同一键，不能每次随机换键绕过现有幂等处理。

用户明确要求“把 F002 用途改为办公资料并保存”时，模型读取当前发票与版本后执行；对象、企业或修改内容缺失时追问。程序检查权限、字段和实际写入范围，模型不自行授予权限。业务服务返回失败时，模型解释原因并据此调整，不能改写成成功。

初始仍使用 1.1.0 的五条规则及现有选择器。规则导入、更新、停用是后续赛题必需工作，但不在本轮再建设一套文档管理系统；主对话跑通后补最小管理入口。

## 7. DeepSeek 如何接入

新增一个小 provider 模块，用现有 ChatOpenAI 的兼容接口：

- 官方地址：`https://api.deepseek.com`。
- 默认模型：`deepseek-flash`。
- **显式**发送关闭 thinking 的配置。不能省略该参数并假设服务端默认关闭。
- 通过配置选择模型、超时、输出长度和密钥来源；密钥继续留在 `D:\AI黑客松\deepseek key` 或由环境变量提供，不复制进项目。
- 仅对该 provider 的 HTTP 客户端使用 `trust_env=False`，直连服务，不改变系统及其他服务的代理。
- 关闭 SDK 隐式重试。对明确限流或短暂不可用，最多一次有界退避；读超时且结果未知时保留未知状态，避免无依据连续重发。业务保存先核对已完成结果。
- 目前只有一个密钥，不建设密钥池。后续若确实新增多个密钥，再处理轮询。
- 先完成 DeepSeek 一条路径，保留 Qwen/比赛统一模型的配置接入点，不在首轮同时做多模型锦标赛。

未来若打开 thinking，需要遵守服务端工具调用历史中 reasoning_content 的传递要求；这是后续可选适配，本轮不增加。

现有 TOML 目前是示例，运行代码还没有完整加载它。下一步增加简单配置加载，并在依赖说明中列出现有环境实际使用的 LangChain/LangGraph/HTTPX 包；不导入旧 editable textile_ai，也不复制整个 ChemIntent 环境依赖清单。

## 8. 实施顺序与真实任务

### 第一个纵向切片

先做最少任务存储、工具包装和 DeepSeek 循环，让下面这条真实对话跑通，不等全部记忆管理和界面做好：

1. U001/C001：“检查 2026 年 9 月还有哪些发票没有填用途。”
2. Agent 查询数据、使用甲企业 2.0 版规则，并保留待办。
3. 用户：“F002 的用途填办公资料，保存。”
4. 程序实际保存并回查；Agent 回复结果，待办随当前数据更新。
5. 关闭程序，创建**不同 session_id 的新会话**：“继续刚才没处理完的事。”
6. 系统按用户/企业恢复任务、重新查询，F002 不应再出现在待补列表。

这是验证任务记忆，不能只恢复同一个 LangGraph thread 就声称跨会话任务管理成立。

### 第二个切片

接入明确长期偏好，并验证新会话使用、更正、删除后不再使用。加入 U002 无权写入、切换企业不串任务、临时查询不覆盖未完事项等真实场景。

### 最后收口

补必要的任务/偏好命令行管理入口和本轮模型输入、规则选择、工具结果的简明记录；再做一次集中回归，检查原有金额与保存能力没有受影响。记录业务结果和失败原因，不以检查数量作为主要交付物。

任务/记忆设计与 Agent/provider 调研可以并行。实施时按 lunaf 约束，由一个写入 worker 负责集成，明确文件所有权；实调进行时可并行整理不依赖结果的说明和后续用例。
