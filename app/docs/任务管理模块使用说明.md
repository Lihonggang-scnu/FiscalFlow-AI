# 发票用途补全任务管理

这是一份给操作人员和初学者的说明。任务记录的是“要把哪件事办完、还剩什么”，
不是发票数据库的副本。金额、用途和规则每次接续时都从当前业务数据重新查询。

## 两种目标范围

- `all_missing`：按当前企业、月份和有效规则列出应补用途的发票。乙企业低于 1000 元的票不会因为金额而自动列入。
- `selected`：用户明确指定发票编号。只要该发票属于当前企业和月份，就可以办理；即使规则本来允许空白，用户指定后也要把用途补成非空才算完成。

## 典型操作

```powershell
$python = 'E:\AI-Chem\ChemIntent\.venv-cpython\Scripts\python.exe'
$env:PYTHONPATH = 'D:\AI黑客松\TaxAgentHarness\src'

# 创建任务，并保存返回的 task_id
$create = (& $python -m taxharness.cli task-create --user-id U001 --company-id C001 --month 2026-09 --scope all_missing | Out-String) | ConvertFrom-Json
$taskId = $create.task.task_id

# 接续当前用户在当前企业的任务，不需要记住 task_id
& $python -m taxharness.cli task-resume --user-id U001 --company-id C001

# 保存前重新读取当前发票 revision，再生成本次操作的幂等键
$current = (& $python -m taxharness.cli query --user-id U001 --company-id C001 --month 2026-09 | Out-String) | ConvertFrom-Json
$invoice = $current.data.invoice.invoices | Where-Object invoice_id -eq 'F002'
$revision = $invoice.revision
$operationKey = 'U001:C001:invoice:F002:' + [guid]::NewGuid().ToString('N')

# 任务内保存用途；返回 committed 后任务会自动刷新待办
& $python -m taxharness.cli task-save-invoice --user-id U001 --company-id C001 `
  --task-id $taskId --invoice-id F002 --purpose '办公资料' --expected-revision $revision `
  --idempotency-key $operationKey
```

`expected-revision` 防止覆盖别人刚保存的版本；同一个幂等键重复提交已经成功的请求，
会返回重放结果，不会再次修改发票。

## 命令查阅

```powershell
# 当前任务和历史
& $python -m taxharness.cli task-list --user-id U001 --company-id C001
& $python -m taxharness.cli task-list --user-id U001 --company-id C001 --include-history

# 详情、刷新、更正、完成检查
& $python -m taxharness.cli task-get --user-id U001 --company-id C001 --task-id $taskId --refresh
& $python -m taxharness.cli task-correct --user-id U001 --company-id C001 --task-id $taskId --month 2026-09 --scope selected --invoice-id F001
& $python -m taxharness.cli task-complete --user-id U001 --company-id C001 --task-id $taskId

# 停止或删除任务；不会撤销已保存的发票用途
& $python -m taxharness.cli task-cancel --user-id U001 --company-id C001 --task-id $taskId
& $python -m taxharness.cli task-delete --user-id U001 --company-id C001 --task-id $taskId
```

## 日常行为

- 临时查询 8 月金额不会改变正在办理的 9 月任务。
- 把任务月份更正为 8 月会返回超出用途检查范围，原 9 月任务保持不变。
- 切换企业只会读取新企业自己的任务；C001/F002 与 C002/F002 是不同发票。
- 关闭程序后，新会话用同一用户和企业即可接续，并会重新核对已经被其他入口修改的数据。
- “取消”停止自动接续但保留历史；“删除”只删除任务入口，不删除发票、流水或已保存用途。

任务 API 和 CLI 均不调用模型。未来 DeepSeek Agent 只负责听懂用户意图和选择这些操作，
用户与企业身份、权限、金额和保存仍由程序控制。

## 规则变化时的任务

规则维护通过本机可信 CLI 完成，不由 Agent 自动写规则。规则版本保留正文和结构化执行条件；新版本导入后，进行中的 `all_missing` 任务在接续时重新读取当前规则和发票，待办会按新条件刷新。`selected` 任务仍按用户明确指定的发票办理。

如果最新适用版本被停用，系统不会静默恢复更旧的 inactive 版本。缺少规则或条件无法自动执行时，任务保留原未完成状态和待办，并明确提示缺少依据；这不会阻止有独立依据的金额查询。
