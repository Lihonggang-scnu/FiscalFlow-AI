# 规则维护模块

规则维护是本机可信 CLI 入口，不由自然语言 Agent 自动写入。规则正文、适用企业、生效日期、状态和程序执行条件一起保存；原始规则正文用于阅读和说明，程序只按结构化 `condition` 执行。

## 查看规则

使用项目已有 Python 环境：

```powershell
$python = $env:TAXHARNESS_PYTHON
if (-not $python) { $python = (Get-Command python).Source }
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$db = 'artifacts/runtime/taxharness.sqlite3'

& $python -m taxharness.cli rule-list --database $db
& $python -m taxharness.cli rule-list --database $db --kind invoice_purpose --company-id C002
& $python -m taxharness.cli rule-get --database $db --rule-id R003 --version 1.0
```

结果会显示规则名称、版本、适用企业、生效日期、active/inactive 状态、原文和执行条件说明。

## 导入一个新版本

将下面内容保存为 `r003-2.json`。金额统一用整数分：500.00 元写作 `50000`。下面的条件表示“单张发票金额大于等于 500.00 元时必须填写用途”：

```json
{
  "rules": [{
    "rule_id": "R003",
    "version": "2.0",
    "name": "乙企业发票用途规则",
    "kind": "invoice_purpose",
    "company_id": "C002",
    "effective_from": "2026-09-01",
    "status": "active",
    "content": "金额达到500.00元时必须填写用途。",
    "condition": {
      "type": "amount_gte",
      "amount_cents": 50000
    }
  }]
}
```

```powershell
& $python -m taxharness.cli rule-import --database $db --file .\r003-2.json
```

`effective_from` 是规则开始适用的日期；查询某个月时按该月第一天选择已生效版本。新版本应使用新的 `version`，不能覆盖已有版本。导入会整批校验，任一条不合法或企业不存在，整批都不会写入。

## 更正、启用和停用

`rule-update` 也用于给已有 `rule_id` 创建新版本，旧版本保持不变；JSON 仍需同时提供正文和 `condition`：

```powershell
& $python -m taxharness.cli rule-update --database $db --file .\r003-3.json
& $python -m taxharness.cli rule-enable --database $db --rule-id R003 --version 3.0
& $python -m taxharness.cli rule-disable --database $db --rule-id R003 --version 3.0
```

停用当前最新版本不会自动恢复旧的 inactive 版本。若只是恢复刚停用的当前版本，明确对同一版本执行 `rule-enable` 即可；若要让旧版条件在同一月份重新适用，应把旧条件作为新的更高版本导入并显式启用。单独启用更老版本不能越过同月已有的更新版本（即使该更新版本已 inactive）。若最新符合日期的版本已停用，系统会返回“无适用规则”，不会把它当作合格，也不会清空进行中的任务待办。

## 条件与任务行为

当前用途条件支持：

- `{"type":"all"}`：每张发票都必须填写用途；
- `{"type":"amount_gte","amount_cents":100000}`：金额大于等于 1000.00 元时必须填写用途。
- `{"type":"none"}`：当前规则不要求填写用途。

其他结构化条件会保留并显示，但返回 `cannot_determine`，不会猜测结果。规则正文中的门槛文字不会替代 `condition`。

规则变化后，进行中的 `all_missing` 任务在接续时重新查询当前规则和发票，待办按新条件刷新；如果规则被停用或不能自动执行，任务保留原 pending 和未完成状态，并在 Agent 上下文提示缺少依据。`selected` 任务仍按用户明确指定的发票办理。规则维护不会修改发票、银行流水或已保存用途。

## 已检查的实际结果

在独立业务副本中，乙企业门槛从 1000 元更新为 500 元后，进行中任务的缺项由 3 张增加到 5 张，包含 600 元的 F001 和 999.99 元的 F004；真实 DeepSeek 回复引用了 2.0 版及新门槛。停用该版后，助手说明暂时无法判定，原任务和待办保持；金额查询仍正常。再次初始化也保留维护结果。

代表性规则验证记录已选摘到 `artifacts/package_records/rules_acceptance.json`；真实办理使用独立副本，默认业务数据及原五条规则原有内容保持不变。
